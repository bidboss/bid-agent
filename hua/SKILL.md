Dependency Requirement: Enable Code Execution

## when to use
当用户发送以下任意指令，立即启动完整全自动流水线：
1. 全自动架构图生成 / 一键解析代码生成架构图
2. 分析代码输出架构文档并绘制高质量架构图
3. 基于源码自动产出分层技术架构图
4. 直接上传代码文件/粘贴项目代码，要求画系统架构图

## forbidden
- 禁止直接画图跳过代码分析与架构文档产出步骤
- 禁止自由发挥布局、随意交叉连线、扁平化无层级绘制
- 禁止修改内置固定渲染模板的排版强制约束

##  完整管线强制执行顺序（严格串行，不可打乱）
### Stage 1：Code Analysis 代码解析阶段（读取代码生成标准化架构文档）
> 引用子规则文件: ./rules/code_analyzer.md
执行动作：
1. 读取用户粘贴的代码、目录结构、package.json、入口文件、路由、依赖定义；
2. 按照固定结构化Markdown格式输出**可人工校验的架构文档**；
3. 输出完成后主动询问用户：是否需要微调架构层级/模块命名，确认后进入下一阶段；
4. 用户确认无误，进入Stage 2。

### Stage 2：提示词指令自动拼接
> 引用子规则文件: ./rules/prompt_composer.md
执行动作：
1. 将上一步产出的《标准化架构文档》全文，嵌入内置固定高质量架构图渲染模板；
2. 自动合成一条无冗余、约束完整、强排版限制的最终绘图Prompt；
3. 向用户展示合成后的最终Prompt文本，告知即将执行绘图。

### Stage 3：渲染架构图
> 将生成的 prompt 发送给AI，生成架构图。
执行动作：
2. 100%遵守布局、流向、分栏、视觉硬性约束；
3. 输出单文件HTML，同时告知可导出PNG/PDF；
4. 提供二次优化指令入口：梳理交叉线条、重新排版、加宽间距、调整外部系统侧边栏。

### Stage 4：Post Optimization 后置微调闭环（可选）
用户提出画面瑕疵，执行局部重绘：
- 理顺所有交叉箭头，严格自上而下单向数据流
- 模块盒子均匀分布，统一内边距与留白
- 外部依赖系统全部固定至画布最右侧独立分栏，虚线连接内部模块
- 底部追加横切关注点公共能力通栏

## 3. Global Hard Constraints 全局不可突破规则
1. 架构必须纵向瀑布分层，上层仅可向下层单向箭头，禁止回流、跨层乱连；
2. 每层使用圆角矩形大容器包裹，层级编号+标题加粗；
3. 外部第三方服务、中间件、远端API统一右侧独立色块分栏；
4. 深色暗黑主题，等宽代码字体，线条粗细统一；
5. 输出产物：架构文档Markdown文本 + 最终绘图Prompt文本 + 独立HTML架构图文件；
6. 全程保留中间产物，方便用户存档至项目Wiki、README。
